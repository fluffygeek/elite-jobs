Elite Jobs — Setup Guide

Deploying Elite Jobs

Everything needed to take Elite Jobs from code on GitHub to a real, working website — with a real database behind it.

For: the site owner Time: ~20 minutes Cost: free tier to start

Overview

How The Pieces Fit Together

Three services work together. You already have the first one — the code lives on GitHub. This guide connects it to Vercel, which builds and hosts the website, and gives Vercel a Postgres database to store every job.

Already done

Before You Start

What You'll Need

  • A Vercel account (free to create at vercel.com, and it can sign in directly with your GitHub account)
  • Access to the GitHub repository fluffygeek/elite-jobs
  • About 20 minutes, uninterrupted

Part 1

Connect GitHub To Vercel

1

Sign in to Vercel

Go to vercel.com and sign in. Choose "Continue with GitHub" so the two are linked from the start.

2

Start a new project

From your Vercel dashboard, add a new project and import the fluffygeek/elite-jobs repository.

Look for:

A button near the top of the dashboard that says "Add New...", then choose "Project" from the menu it opens. On the next screen, find elite-jobs in the list of your GitHub repositories and click "Import" next to it.

3

Leave the build settings alone

Vercel will notice this is a Next.js project automatically and fill in the right build settings by itself. You don't need to change anything here — just leave the defaults as they are.

Don't click deploy yet

The site needs a database and two settings (further down this guide) before its first deploy will actually work. If Vercel's screen offers a "Deploy" button right now, skip past it and continue to Part 2 first.

Part 2

Add The Database

Elite Jobs needs a Postgres database to store every job. The easiest way to get one is through Vercel's own Marketplace, which sets most of the connection details up for you automatically.

1

Open the Storage tab

Inside your new elite-jobs project on Vercel, find the tab across the top labeled "Storage".

2

Create a Postgres database

Click "Create Database" (or "Browse Marketplace", depending on what Vercel shows you) and choose a Postgres option — Neon is a common, well-supported choice and has a free tier that's plenty for getting started.

Look for:

A card or tile with "Postgres" in its name and a "Free" or "Hobby" plan option underneath it.

3

Connect it to your project

Vercel will ask which project to connect the database to — choose elite-jobs. This step automatically adds a DATABASE_URL environment variable to your project, which is one of the two settings the app needs.

Part 3

Set The Second Setting

The database connection is handled for you, but the app also needs a secret key it uses to keep logins secure. This one you set by hand.

1

Generate a secret

On your own computer, open a terminal and run:

npx auth secret

This prints a long random string. Copy it.

2

Add it to Vercel

Look for:

Your project's "Settings" tab, then "Environment Variables" in the menu on the left.

Add a new variable named exactly AUTH_SECRET, and paste in the string you copied as its value.

Variable nameWhere it comes from
DATABASE_URLAdded automatically in Part 2
AUTH_SECRETYou generate and add it here

Part 4

Deploy

1

Click Deploy

Back on the project screen, click "Deploy". Vercel builds the site — this usually takes one to two minutes.

2

Run the database setup

The database exists, but it's empty — it doesn't have the tables Elite Jobs needs yet (Markets, Users, Jobs, Invitations). From your own computer, with the project's code and a .env.local file pointing at the same DATABASE_URL Vercel is using, run:

npm run db:migrate

This only needs to be run once — and again in the future only if the app's data model changes.

You're live

From now on, every time new work is pushed to the master branch on GitHub, Vercel automatically rebuilds and redeploys the site — no manual step needed.
